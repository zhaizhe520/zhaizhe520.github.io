pixi.js@7 可能与 pixi-live2d-display 不兼容，版本冲突会出现 read(0) 索引 0 的问题

我遇到一个Bug：

模型加载时报 read(0)。排查发现是 PixiJS 7 和 pixi-live2d-display 的版本不兼容，底层 WebGL 数据结构变了。

我通过锁定 PixiJS 6.5.10 + Cubism 5.2 解决。

这让我学会：图形库的版本兼容性比普通库更敏感，因为涉及底层渲染管线。

核心是闭源的，必须放到 public/ 下，否则会被 Vite 编译导致失效

Cubism SDK 是闭源的，必须作为全局脚本在模块加载前就绪。

但 Vite 会处理 public/ 之外的资源，所以我把核心库放 public/，并在 index.html 里手动控制加载顺序。

这让我理解了构建工具的资源处理边界，以及全局脚本和 ES 模块的加载时序差异。

窗口缩放 bug 每次缩小浏览器视窗，canvas 画布不会随之改变，导致 Live2D 模型可能在缩放后的视窗外，必须刷新才能解决

设计问题: 就是canvas画布一开始是全屏的覆盖的，不能是覆盖的导致浏览器窗口缩小画布不锁小，蛮搞笑的live2d在浏览器窗口外面了

我遇到一个没完全解决的问题：窗口缩小时，canvas 的 resize 触发了，但模型位置没重新计算，导致模型跑出视窗。我怀疑是 PixiJS 的 resize 和模型的 x/y 是独立计算的，没有做边界约束。

我的思路是：在 resize 回调里重新计算模型位置，加上碰撞边界检测，让模型始终在视窗内。这个问题让我意识到渲染循环和业务逻辑的耦合需要解耦

Vue 指令封装 + 打字机 → 能讲“解耦与组合式函数

v-pet-tps = “‘’” 给dom元素绑定

我把气泡文本、打字机、表情触发都封装成 Vue 指令和组合式函数，而不是在组件里堆逻辑。

核心是解耦：指令负责 DOM 事件绑定，组合式函数负责状态，Live2D 模型通过 window 暴露给指令调用。

这让我理解Vue 指令的生命周期，以及跨模块通信的取舍（全局挂载 vs 事件总线 vs 状态管理）。
